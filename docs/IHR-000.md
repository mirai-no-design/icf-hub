## 1. 目的

IHR（ICF Hub Request for Comments）は、ICF Hub / Service Registry に関する仕様・規約・運用ルールを、誰のものでもない公開文書として蓄積するための文書シリーズである。

IHRはインターネットのRFCの作法にならう。すなわち、

- 誰でも無料で読める
- 誰でもコメントできる（名前のとおり「コメント募集」が本質である）
- 議論の記録ごと公開される
- 特定の企業・団体の所有物にならない
- 一度発番された文書は改変せず、変更は新しい文書または改訂版として積み重ねる

ことを原則とする。仕様をオープンに公開すること自体が防衛的公開（先行技術化）であり、コモンズとしての仕様を第三者による囲い込みから守る。

## 2. 番号体系

- 番号は `IHR-NNN`（3桁ゼロ埋め）とし、000から昇順に発番する
- 番号は再利用しない。廃止された番号は欠番として残す
- IHR-000（本文書）はプロセス自体を定義する。IHR-001以降が実体の仕様である
- 番号は編集者（Editors）が草稿受理時に採番する。番号の予約はできない

## 3. ステータス

| ステータス | 意味 |
|---|---|
| Draft | 草稿。内容は変わり得る。実装は歓迎するが追随の責任は負わない |
| Review | コメント募集期間中。Issueでの議論を経て採択判断を行う |
| Accepted | 採択済み。以後、本文の意味を変える変更は行わない（誤字等の軽微な修正を除く） |
| Superseded | 新しいIHRに置き換えられた。ヘッダに後継番号を明記する |
| Withdrawn | 取り下げ。理由をヘッダに明記する |

## 4. プロセス

1. **提案**: 提案者は `IHR-TEMPLATE.md` を複製して草稿を書き、Pull Requestを作成する
2. **受理・採番**: 編集者が形式要件（テンプレート準拠・ライセンス同意）を確認し、番号を採番してDraftとしてマージする
3. **コメント募集**: Issueで議論する。実装からのフィードバック（Familyシリーズ等の接続実装、レジストリの登録実運用）を特に重視する
4. **採択**: 編集者会が合意を確認しAcceptedとする。合意の基準は全会一致ではなく「持続的な反対がないこと（rough consensus）」とする
5. **改訂**: Acceptedの内容を変える場合は新しいIHRを起こし、旧IHRをSupersededにする

## 5. 文書の要件

- 言語は日本語を基本とする。国際発信の必要に応じて英語要旨（Abstract）を付す
- 形式はMarkdown。図はMermaid記法をコードブロックで埋め込む（レンダリング環境に依存しないため）
- 各IHRは冒頭に番号・タイトル・ステータス・作成日・著者・ライセンスのヘッダ表を持つ
- 仕様の規範的な語（しなければならない/すべきである/してもよい 等）は、必要に応じてRFC 2119の慣例に準じて定義して用いる

## 6. 編集者（Editors）

- 編集者はリポジトリの管理と採番・採択判断を行う。初期編集者はプロジェクト発起人が務める
- 編集者は特定組織の利害を代表しない。将来的には協議会等の中立的な運営主体への移管を予定する（本リポジトリREADME・IHR-001参照）

## 7. ライセンスと公知化

- すべてのIHRは CC BY 4.0 で公開する。Pull Requestの提出をもってライセンスに同意したものとみなす
- リリース（タグ）ごとにZenodo連携によりDOIを付与し、公開日時の第三者証明を得る
- 本シリーズの内容について、いかなる者も排他的権利（特許等）を取得しないことを期待する。防衛的公開のため、重要な設計はIHRとして速やかに文書化する

## 8. 名称について

「ICF Hub」等の名称は、仕様の品質と信頼を守る目的で商標登録されることがある（仕様はオープン・名称は保護の方式）。商標の有無はライセンス（CC BY 4.0）による仕様の利用可能性に影響しない。
